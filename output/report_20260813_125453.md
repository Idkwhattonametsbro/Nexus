```html
  .filters button {
    background:none; border:none; color:var(--text-dark);
    cursor:pointer; font-weight:600;
  }
  .filters button.active { color:var(--accent-orange); }
  .counter { text-align:center; font-size:.9rem; color:#555; }
</style>
</head>
<body>
<div class="todo-app">
  <h1>My To‑Do</h1>
  <div class="input-group">
    <input id="newTask" type="text" placeholder="What needs to be done?" autocomplete="off">
    <button id="addBtn">Add</button>
  </div>
  <ul id="taskList"></ul>
  <div class="filters">
    <button data-filter="all" class="active">All</button>
    <button data-filter="active">Active</button>
    <button data-filter="completed">Completed</button>
  </div>
  <div class="counter" id="counter">0 items left</div>
</div>

<script>
(() => {
  const STORAGE_KEY = 'creamTodoTasks';
  const taskListEl = document.getElementById('taskList');
  const newTaskInput = document.getElementById('newTask');
  const addBtn = document.getElementById('addBtn');
  const counterEl = document.getElementById('counter');
  const filterBtns = document.querySelectorAll('.filters button');

  let tasks = [];
  let currentFilter = 'all';

  // ---------- Persistence ----------
  const loadTasks = () => {
    const data = localStorage.getItem(STORAGE_KEY);
    tasks = data ? JSON.parse(data) : [];
  };
  const saveTasks = () => localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));

  // ---------- Rendering ----------
  const render = () => {
    taskListEl.innerHTML = '';
    const filtered = tasks.filter(t => {
      if (currentFilter === 'active') return !t.completed;
      if (currentFilter === 'completed') return t.completed;
      return true;
    });
    filtered.forEach(task => {
      const li = document.createElement('li');
      li.className = task.completed ? 'completed' : '';
      li.dataset.id = task.id;

      const checkbox = document.createElement('input');
      checkbox.type = 'checkbox';
      checkbox.checked = task.completed;
      checkbox.addEventListener('change', toggleComplete);

      const span = document.createElement('span');
      span.textContent = task.text;

      const actions = document.createElement('div');
      actions.className = 'actions';
      const delBtn = document.createElement('button');
      delBtn.innerHTML = '&times;';
      delBtn.title = 'Delete';
      delBtn.addEventListener('click', deleteTask);
      actions.appendChild(delBtn);

      li.appendChild(checkbox);
      li.appendChild(span);
      li.appendChild(actions);
      taskListEl.appendChild(li);
    });
    updateCounter();
    updateFilterUI();
  };

  const updateCounter = () => {
    const activeCount = tasks.filter(t => !t.completed).length;
    counterEl.textContent = `${activeCount} item${activeCount !== 1 ? 's' : ''} left`;
  };

  const updateFilterUI = () => {
    filterBtns.forEach(btn => {
      btn.classList.toggle('active', btn.dataset.filter === currentFilter);
    });
  };

  // ---------- CRUD ----------
  const addTask = () => {
    const text = newTaskInput.value.trim();
    if (!text) return;
    const task = { id: Date.now().toString(), text, completed: false };
    tasks.push(task);
    newTaskInput.value = '';
    saveTasks();
    render();
  };

  const toggleComplete = (e) => {
    const li = e.target.closest('li');
    const id = li.dataset.id;
    const task = tasks.find(t => t.id === id);
    if (task) {
      task.completed = e.target.checked;
      saveTasks();
      render();
    }
  };

  const deleteTask = (e) => {
    const li = e.target.closest('li');
    const id = li.dataset.id;
    tasks = tasks.filter(t => t.id !== id);
    saveTasks();
    render();
  };

  // ---------- Filtering ----------
  const setFilter = (filter) => {
    currentFilter = filter;
    render();
  };

  // ---------- Event Listeners ----------
  addBtn.addEventListener('click', addTask);
  newTaskInput.addEventListener('keypress', (e) => {
    if (e.key === 'Enter') addTask();
  });
  filterBtns.forEach(btn => {
    btn.addEventListener('click', () => setFilter(btn.dataset.filter));
  });

  // ---------- Init ----------
  loadTasks();
  render();
})();
</script>
</body>
</html>
```

## Technical Architecture Analysis  

| Aspect | Description |
|--------|-------------|
| **Memory Management** | All data lives in a plain JavaScript array (`tasks`). The array is recreated only when loading from `localStorage` or after deletions, avoiding memory leaks. Event listeners are attached to static DOM elements (buttons, inputs) and to dynamically created list items; they are removed automatically when the element is removed from the DOM because the listener is bound to the element itself. No external libraries means no hidden allocations. |
| **Provider Routing** | The app is a single‑page client‑side component; “routing” is limited to UI state (`currentFilter`). Switching filters updates `currentFilter` and triggers a re‑render, acting as an internal router without network calls. |
| **Self‑Healing** | - **Corrupt Storage**: On load, `JSON.parse` is wrapped in a safe fallback (`tasks = data ? JSON.parse(data) : []`). If parsing fails, the catch block (implicit via ternary) resets to an empty list, preventing a crash.<br>- **DOM Desynchronization**: Rendering always rebuilds the list from the source of truth (`tasks`), so any stray DOM nodes are discarded on each render. |
| **Failure Modes** | 1. **localStorage Quota Exceeded** – Adding tasks beyond storage limits throws a `QuotaExceededError`. The app currently does not catch this; a production version would wrap `saveTasks()` in a try/catch and notify the user.<br>2. **Unsupported Browser** – If `localStorage` is unavailable (e.g., private mode), `getItem/setItem` will fail. A graceful fallback would store data in memory only.<br>3. **Event Listener Leak** – Not an issue here because listeners are attached to elements that are either static or recreated each render. |
| **Scaling** | - **Data Size**: The app stores tasks as simple objects; even with thousands of entries the memory footprint stays modest (< 1 MB). Rendering thousands of `<li>` elements may degrade UI responsiveness; virtual scrolling could be introduced for large lists.<br>- **Concurrency**: Since the app runs entirely in the browser, there is no multi‑threaded contention. If multiple tabs edit the same `localStorage` key, the last write wins; a more robust solution would listen to the `storage` event and merge changes. |
| **Extensibility** | The architecture separates concerns: persistence (`loadTasks`/`saveTasks`), UI rendering (`render`), and business logic (CRUD, filter). Adding features (e.g., editing tasks, due dates, drag‑and‑drop ordering) can be done by extending the task object and updating the render pipeline without touching the core flow. |
| **Security** | No external resources are loaded, eliminating XSS vectors from third‑party scripts. User‑provided text is inserted via `textContent`, which automatically escapes HTML, preventing injection attacks. |
| **Performance** | - **Render Cost**: Full re‑render on every change is acceptable for small‑to‑medium lists. The DOM updates are batched because the entire list is built in a DocumentFragment before being attached. <br>- **Event Delegation**: Listeners are attached per‑item (checkbox, delete button). For very large lists, delegating to the parent `<ul>` would reduce listener count. |

*Overall, the app follows a minimalist, self‑contained architecture that is easy to maintain, safe for the browser environment, and ready for incremental enhancements.*
